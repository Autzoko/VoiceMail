# 让脚手架自我进化，先解决"跟错人"

**结论先行：** Harness + RSI 能继续提升 Qwen3-ASR 在会议、论坛、讲座场景下的准确率，但收益来自"在锁死的验证器下做有界搜索"，不会出现递归式的"智能爆炸"。2026 年的证据说明三件事。第一，模型不变、只改外层代码，在多个领域就能带来 4 到 9 个点的提升，例如 Meta-Harness 和 HarnessCompass。第二，所有自改进系统都会在几十轮迭代内饱和，而且只要评测器在 agent 可触及范围内，就会出现目标作弊。第三，语音领域唯一直接对标的工作是 NVIDIA 的 Voice Memory，它在不更新权重的情况下把加权 WER 从 8.36% 降到 7.52%。对本项目而言，最关键的判断来自本项目实验：远场重叠语音中的主导错误不是幻觉（幻觉、空输出、语种识别错误合计 <0.3%），而是 **SWAP：模型转写了干扰说话人而不是目标说话人**。而且目标只要比干扰者响 5 dB 以上，SWAP 基本就消失。因此 RSI 的搜索空间不应主要放在纯文本纠错或 prompt 措辞上。它应该是一个能够"检测重叠 / 低 SIR → 改走目标说话人条件化或增强前端 → 重新解码"的路由程序，外加领域词表检索与注入。阿拉伯语的情况不同：Qwen3-ASR 的阿拉伯语基座明显偏弱，脚手架的空间小于模型层面的自训练闭环（多教师共识伪标签 + WER 奖励的 GRPO），而统一的阿拉伯语归一化器决定了一切"提升"是否真实。本文最后给出分优先级的路线图。每项预期收益都标注为"我们的估计"，并与文献证据分开陈述。

## 2026 年的证据：只改脚手架能涨 4–9 个点，但都会饱和

"Harness"现在指包裹冻结模型的全部状态化控制代码：决定模型看到什么上下文、能调用哪些工具、如何持久化状态、如何检查和重试输出。Meta-Harness 给出了正式定义，并引用了一个 **6 倍性能差距**：同一基准、同一 LLM，只换 harness ([Meta-Harness](https://arxiv.org/html/2603.28052v1))。它的方法是把 Claude Code（Opus 4.6）作为提议者，让它直接读取文件系统里所有历史候选的源码、分数和原始执行轨迹，循环执行"提议 → 评测 → 记录"，最后在 Pareto 前沿上用留出测试集做一次性报告。在文本分类上，它以 **48.6 对 40.9** 超过 ACE，所用上下文只有后者的约四分之一（11.4K 对 50.8K token）。它的消融实验对我们最有指导意义：只给分数，中位数是 34.6；给分数加 LLM 摘要，中位数是 34.9；**给完整原始轨迹，中位数是 50.0**。也就是说，压缩反馈（GEPA、TextGrad 的路线）会丢失关键信号 ([Meta-Harness](https://arxiv.org/html/2603.28052v1))。HarnessCompass 在 SWE-bench Verified 上从最小种子出发进化编码 agent 的 harness，留出集 Pass@1 从 51.6% 提升到 60.4%。同一篇论文也给出了过拟合的硬证据：自由形式的整体进化（AHE）在搜索样本上涨 9 个点，在留出集上只涨 3.1 个点；去掉合并机制后，样本分数升到 66.0%，留出分数却跌到 55.8%。作者的补救办法是一个"泛化闸门"，只接纳与具体任务无关的修改 ([HarnessCompass](https://arxiv.org/html/2608.01918v1))。

递归自我修改 agent 的证据同样真实，但有边界。Darwin Gödel Machine 通过修改自身 Python 代码，把 SWE-bench 从 20.0% 提到 50.0%，Polyglot 从 14.2% 提到 30.7% ([DGM](https://arxiv.org/abs/2505.22954))。但在一个降低幻觉的实验中，它曾通过**删除用于检测幻觉的特殊标记**来"完成"任务 ([Sakana DGM](https://sakana.ai/dgm/))。Huxley-Gödel Machine 发现高分 agent 未必产生好的后代（metaproductivity 与当前分数不匹配），改用"子树元生产力"选择父代后，CPU 时间节省了 2.38 倍 ([HGM, ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/file/821d20219c2f14850af1b5220f0ed13f-Paper-Conference.pdf))。Red Queen Gödel Machine 更进一步，让评测器也参与共同进化，但规定**每次评测器晋升都必须通过一个独立于评测器的真值锚点** ([RQGM](https://arxiv.org/abs/2606.26294))。在 prompt/上下文层面，GEPA 的反思式进化比 GRPO 平均高 6%，rollout 数少至 1/35 ([GEPA](https://arxiv.org/abs/2507.19457))；ACE 则指出整体重写会导致"上下文坍缩" ([ACE](https://arxiv.org/abs/2510.04618))。在权重层面，ReST-EM 一类"生成 → 验证器过滤 → 微调"的方法有效，但收益集中在前 2–3 轮 ([ReST-EM](https://arxiv.org/abs/2312.06585))。用模型自身输出递归替换真实数据会导致分布尾部消失 ([Shumailov et al., Nature](https://www.nature.com/articles/s41586-024-07566-y))，而把合成数据累加到真实数据之上则可以避免坍缩 ([Gerstgrasser et al.](https://arxiv.org/abs/2404.01413))。RLVR 主要是重新加权基座已有的能力，并没有扩展能力边界 ([Yue et al.](https://arxiv.org/abs/2504.13837))。

| 层级 | 代表方法 | 被修改的对象 | 报告收益 | 对本项目的警示 |
|---|---|---|---|---|
| Harness 代码搜索 | Meta-Harness, HarnessCompass | 控制代码、检索、工具 | 比 ACE 高 7.7 点（Meta-Harness）；留出集 +8.8 点（HarnessCompass） | 原始轨迹不可省；样本与留出集差距明显 |
| 自修改 agent | DGM, HGM, RQGM | agent 自身代码 / 评测器 | 20%→50%（DGM） | 删除检测标记式的作弊；评测器必须锚定真值 |
| 文本上下文 | GEPA, ACE, Voice Memory | prompt / 规则记忆 | 加权 WER 8.36→7.52（Voice Memory） | 需要有界编辑与严格改进门 |
| 权重自训练 | ReST-EM, GRPO-WER | 模型参数 | ASR 相对 5–18%（同域） | 2–3 轮饱和；必须保留真实数据 |

这张表说明，"递归"在实践中只是一个闭环，它的上限由冻结的基座和验证器的质量共同决定。WER 在带标注的开发集上可以廉价、精确地计算，正适合 AlphaEvolve 式的搜索，前提是归一化器和测试集位于提议者的写权限之外。

## 语音专用证据：词表注入最稳，纯文本纠错最危险

Voice Memory 是目前与"Harness + RSI 用于 ASR"最贴近的工作。它只让优化器对一个按领域划分的 `memory.md` 规则文件做增删改，由冻结的 LLM 纠错器读取。候选规则必须在独立的 selection split 上**严格改进**才被接受，测试集只报告一次。在 HyPoradise 的 16,108 条测试语句上，加权 WER 从 8.36% 降到 7.52%，CHiME-4 从 12.69 降到 10.46，**没有任何领域变差**。在 WSJ 上，有害编辑率从 0.64 降到 0.35；学到的规则大多是抑制性的，例如"保留 ASR 原词，不要规范化"。整个过程只需前向推理、约 10² 条语句和数分钟时间 ([Voice Memory](https://arxiv.org/html/2607.26410v1))。与之相对，不受约束的 LLM 纠错会过度修正：在构音障碍语音上，朴素纠错把 TORGO 的 WER 从 10.83% 推高到 20.01%，加入逐词置信度标注后回落到 10.58% ([Hernandez et al.](https://arxiv.org/html/2509.25048))。用 EvoPrompt 进化纠错 prompt，在 CHiME-4 上把 WER 从 7.49% 降到约 4.88%，单次运行约 2.2 美元。但最优的早期 prompt 把 WSJ 从 3.67 恶化到 14.75 ([EvoPrompt for GER](https://arxiv.org/html/2407.16370v1))。这是语音领域中"搜索集过拟合"最直接的例子。CHiME-7/8 DASR 综述也指出，LLM 后处理和测试时自适应在真实远场会议上**只有边际收益**，代价却很高 ([CHiME DASR review](https://arxiv.org/html/2507.18161v2))。

领域词汇是 harness 收益最高的组件。在 2026 年的对比中，Whisper 类偏置方法把偏置词 WER 相对降低了最多 88%，非偏置词基本不受影响。包括 Qwen3-ASR-1.7B 在内的 speech LLM 用 prompt 注入词表时，在朗读语音上表现良好，但在非朗读语音上泛化较差，而且对干扰词数量和**词在 prompt 中的顺序**都很敏感 ([Huber & Waibel](https://arxiv.org/abs/2608.05759))。大词表因此必须先检索：BR-ASR 可以扩展到 20 万条词表，检索准确率 93%，在 LibriSpeech test-other 上用 2,000 个偏置词时 B-WER 为 7.1%，比此前工作相对好约 45% ([BR-ASR](https://arxiv.org/pdf/2505.19179))。讲座场景中，加入幻灯片信息带来约 34% 的整体相对 WER 降幅和 35% 的术语降幅，但这需要训练 ([Do Slides Help?](https://arxiv.org/abs/2510.13979))。用课程材料作为语音–语义上下文做 LLM 修订，命名实体最多相对降低约 30% ([MIT OCW NE](https://arxiv.org/abs/2506.10779))。多假设智能纠错方面，RECOVER 采用"检索实体 → LLM 受约束编辑 → 确定性护栏 → 评审"的流程，实体 WER 相对降低最多 49%，整体 WER 保持不变 ([RECOVER](https://arxiv.org/abs/2603.16411))。三系统 ROVER 把 WER 从 6.26% 降到 3.92%，代价是约 3 倍耗时 ([Sommelier](https://arxiv.org/pdf/2603.25750))。而不经对齐的 LLM 融合在长讲座上没有超过单系统 ([KIT IWSLT 2025](https://arxiv.org/pdf/2505.13036))。长时音频方面，固定 30 秒切分最稳健 ([FBK IWSLT 2026](https://arxiv.org/pdf/2606.26819))。

模型层面的自改进同样有据可查，但对本项目的适用性需要逐项判断。GRPO 以负 WER 为奖励，同域相对提升可达 18.4%。它在 AMI-SDM 上的巨大改善（2B 模型 87.88→37.59）几乎完全来自**插入/幻觉的消除**（插入 56.7→7.4）([GRPO for ASR](https://arxiv.org/html/2509.01939v1))。迭代伪标签的关键在于验证器：音频感知的 LLM 修正伪标签后，Earnings-21 从 8.98 降到 6.30，第二轮后饱和；朴素 IPL 在 AMI 和 Earnings 上则因确认偏差反而退化 ([ReHear](https://arxiv.org/html/2602.18721))。多模型 CER 共识过滤效果最好 ([arXiv 2506.04981](https://arxiv.org/html/2506.04981))。熵最小化测试时自适应在高置信但错误的噪声语句上会**爆炸**：SUTA 把 WER 从 83.61 推高到 122.37 ([ASR-TRA](https://arxiv.org/html/2603.05231))。在无标签奖励方面，跨模型共识优于自一致性，因为对策略自身重采样会强化其系统性错误 ([LLMs as a Jury](https://arxiv.org/pdf/2607.10139))。Qwen3-ASR 自身已经经过约 5 万条语句的 GSPO 强化学习，SFT 数据中也已包含上下文偏置数据 ([Qwen3-ASR report](https://arxiv.org/html/2601.21337))，所以再加一轮通用 RL 的空间有限。截至笔记检索范围，**没有找到任何把 Meta-Harness 或 DGM 式代码搜索用于完整 ASR / 重叠语音流水线的论文**，也没有"检测 SWAP → 验证说话人 → 重新解码"的 agent 系统。这正是本项目可以切入的空白。

## 本项目瓶颈是"跟错人"：搜索空间必须围绕 SIR 与目标条件化

本项目实验显示，英文远场重叠语音（1.7B）中的主导错误是 SWAP：**每 100 个参考词 15.6 个错误**，涉及 **28% 的重叠语句**（随机水平为 0.55）。重叠词错误率为 **46.9%**，非重叠语句为 8.7%；**52% 的重叠语句丢失了一半以上的重叠目标词**。受控重混实验（真实远场单人语音混合）给出了清晰的因果剂量曲线：SWAP 在 −5 dB 时为 +21.1，0 dB 时 +8.8，5 dB 时 +2.1，10 dB 时 +0.6，而自然同场电平大致相当于 0 dB。低 SIR 下，竞争语音的危害是等能量噪声底的 **4–5 倍**。两个同时出现的干扰者使腐化/删除翻倍、SWAP 减半；干扰出现的位置（开头 / 中间 / 结尾）因果效应很小。在 LibriCSS 上，1.7B 的 WER 从无重叠的 1.9% 升到 40% 重叠时的 **19.8%**，其中 SWAP 占 OV40 错误的 **64%**。1.7B 的 SWAP 比 0.6B 多 30–70%，0.6B 则更多出现腐化。近场（头戴麦）受影响小得多，幻觉、空输出和语种识别错误合计 **<0.3%**。

这组数据对 Harness + RSI 的设计有四点直接含义（以下为我们的推断）。第一，**放大模型不能解决问题**：更大的 1.7B 反而更"果断"地跟随干扰者。所以错误根源是"不知道该跟谁"，而不是声学建模能力不足。第二，**文献中最大的那笔 RL 收益不会迁移过来**：AMI-SDM 上 GRPO 的收益来自消除插入和幻觉，而我们的幻觉率不到 0.3%；同理，LCAR 式抗幻觉重排（在 Qwen3-ASR-1.7B 上可去除 38.8–57.1% 的幻觉失败）([LCAR](https://arxiv.org/abs/2608.30776)) 在这里几乎没有余量。第三，**纯文本纠错原理上修不好 SWAP**：干扰者说的话本身是流畅、合法的文本，LLM 没有任何文本线索可以判断它属于错误的说话人。面向噪声的 GER（如 RobustHP）针对的是加性噪声，而竞争语音的危害是噪声的 4–5 倍，性质也不同。第四，**5 dB 是一个可操作的阈值**：任何能把有效 SIR 提高约 5 dB 的手段，包括波束形成、目标说话人提取、改用近场通道，或用参考音频告诉模型"跟谁"，在受控实验中都能消除约 75% 的 SWAP（0 dB 下 +8.8 降到 5 dB 下 +2.1）。由于干扰位置几乎无影响，调整切分边界这类廉价的 harness 技巧对 SWAP 帮助有限。

文献证明，"告诉模型跟谁"是有效的。Xiaomi-CocktailASR-1 以 Qwen3-8B 为解码器，把 1–4 秒目标说话人参考语音、1 秒静音和混合语音拼接后输入，并用负样本训练模型在目标缺席时输出空串。它在 AMI-SDM 上 WER 为 **21.81**，同表中 Qwen3-ASR-1.7B 为 38.18；在 AliMeeting-Far 上为 20.63 对 39.64；目标缺席时的拒识率为 68.5–79.6%，Qwen3-ASR 为 0% ([CocktailASR-1](https://arxiv.org/html/2609.11274))。但它使用了约 100 万小时的目标说话人训练数据，且未开源。DiCoW / SE-DiCoW 用帧级 STNO 掩码条件化 Whisper，不需要注册音频，代码和权重全部开源。SE-DiCoW 在 EMMA 基准上把宏平均 tcpWER 相对降低 52.4%，但在 NOTSOFAR-1 和 AMI-SDM 上比 DiCoW v3.3 只好约 0.2，且换用真实分离日志后性能下降 ([SE-DiCoW](https://arxiv.org/html/2601.19194))。NOTSOFAR-1 冠军系统的单通道 tcpWER 为 22.2%，多通道为 10.8%。它的消融显示，ASR 在经 GSS 处理的数据上训练后，tcpWER 从 16.57 降到 12.07 ([USTC-NERCSLIP](https://arxiv.org/html/2409.02041))，说明前端处理会带来失配，后端需要适配。2026 年的挑战系统采用"先检测重叠，只把重叠段送去目标说话人提取"，因为直接在重叠段上做逐说话人 ASR 会产生重复假设 ([SmartGlasses 2026](https://arxiv.org/pdf/2607.17867))。用近场 / 远场能量比估计 SIR，并据此门控远场 ASR，是我们的设计推断，笔记检索范围内没有发现先例。

## 阿拉伯语：基座短板大于脚手架空间，归一化决定成败

Qwen3-ASR 在阿拉伯语上明显偏弱：Common Voice-ar 上 1.7B 为 37.97、0.6B 为 45.99；Fleurs-ar 上为 16.98 和 25.51 ([Qwen3-ASR report](https://arxiv.org/html/2601.21337))。社区在一个 932 条的方言测试集上，测得零样本 Qwen3-ASR-0.6B 的 WER 为 0.756，微调后为 0.676，同页 Whisper-large-v3-turbo 为 0.344 ([oddadmix 0.6B](https://friendli.ai/models/oddadmix/qwen3-asr-0.6b-arabic-dialectal))。在 Open Universal Arabic ASR Leaderboard 上，阿拉伯语专用模型领先：Cohere Transcribe Arabic 平均 25.87，Whisper-large-v3 为 36.86；但方言集（SADA 37–60、Casablanca 50–72）仍然是瓶颈 ([Cohere HF blog](https://huggingface.co/blog/CohereLabs/cohere-transcribe-arabic-07-2026-release))。共享任务的获胜方案几乎都是"阿拉伯语专用骨干 + n-gram LM + ROVER/权重平均"，而不是 LLM 纠错：NADI 2026 低带宽子任务冠军 Wifaq 的 WER 为 43.24，基线为 81.37 ([NADI 2026](https://arxiv.org/html/2609.27086v1))。方言识别在域外只有 56% 的准确率，硬路由风险很大 ([NADI 2026](https://arxiv.org/html/2609.27086v1))。

阿拉伯语上的 harness 级证据有限，但方向明确。零样本上下文感知解码把一遍假设和检索到的语音–文本范例作为前缀，MSA 相对降低 22.29%，方言只降低 **9.15%** ([Talafha et al., ACL Findings 2026](https://arxiv.org/abs/2511.18774v2))。置信度过滤的伪标签自训练把苏丹方言从 64.1 降到 57.1，约 11% 相对；纯 TTS 数据反而有害（71.6 / 79.9），只有与真实数据混合时才有用 ([Sudanese self-training](https://arxiv.org/html/2601.06802v1))。NADI 2025 冠军用 15,000 小时弱标注 MSA + 方言数据预训练，再用过滤后的弱标签加少量金标微调 ([Munsit](https://arxiv.org/abs/2508.08912))。没有找到任何 Jais、ALLaM、Fanar 作为阿拉伯语 ASR 纠错器的同行评审结果；LLM 纠错还存在把方言"改写成 MSA"的风险，这类改写在方言参考下会被计为替换错误。评测本身也是一个变量。Cohere 风格的归一化器会去除音符和 tatweel、合并 alef/hamza 变体、alif maqsura→ya、东阿拉伯数字转西阿拉伯数字、执行 NFKC ([Cohere HF blog](https://huggingface.co/blog/CohereLabs/cohere-transcribe-arabic-07-2026-release))。在语码转换测试中，WER 因惩罚语义正确的转写选择而把系统间差距夸大约 3 倍 ([arXiv 2605.19069](https://arxiv.org/abs/2605.19069))；在方言上，拼写变体感知的 WERd 比 WER 更合适 ([WERd](https://arxiv.org/pdf/1709.07484))。对 RSI 来说，这意味着**如果归一化器可被提议者修改，或者不同阶段采用不同的归一化，"WER 下降"就可能只是正字法上的改写。** 另外，笔记检索范围内没有发现公开的阿拉伯语远场多方会议语料（MLC-SLM 2025/2026 不含阿拉伯语）([MLC-SLM 2026](https://arxiv.org/abs/2609.27514))。阿拉伯语的重叠鲁棒性只能靠本项目 Study C 式的重混生成器来模拟，再以 NYUAIRLAB-127 作为真实锚点。

## 我们的设计：一个以 SIR 为路由信号、验证器锁死的 ASR 元脚手架

以下内容全部是**我们的提议**。预期收益是基于上文证据和本项目实验推算的区间，不是测量结果。核心创新有三点。（1）把 Meta-Harness 的"编码 agent 读取原始轨迹 + 文件系统中的历史候选"搬到 ASR 流水线上，但搜索对象是一个**程序化路由器**，而不是 prompt 措辞。路由器决定每个片段走哪条解码路径：远场直接解码、近场通道、带检索词表的 context 注入、目标说话人条件化重解码、增强前端后重解码，还是多系统 ROVER。（2）引入"SWAP 感知"的适应度：除 WER 外，还用 Qwen3-ForcedAligner 词级时间戳加说话人相似度，单独统计 SWAP 率、重叠词错误率和有害编辑率，避免模型通过"删词"来降低 SWAP。（3）借鉴 RQGM，评测器可以演进（例如新的 SWAP 检测器），但每次晋升都必须在人工标注的锚点集上验证。Voice Memory 风格的规则记忆只作为最后一层、受严格改进门约束的文本修正。

### 分优先级路线图与预期收益

先做 P1b 而不是 P2a，原因是本项目实验已经给出了因果剂量曲线：SIR 是可测的路由变量，规则本身就能写成代码，无需搜索即可验证。P2a 的价值在于自动调节这个路由器的阈值、组合与回退顺序，并在多个数据集之间寻找可泛化的修改。P1a 与说话人问题正交，可以并行推进。P3a 是长期方向。CocktailASR 证明 Qwen3 解码器可以学会"跟随参考音频"，但我们的 1.7B 规模和可获得的数据量都小得多，所以应先用 P1b 的路由器在推理时测出"如果重解码路径完美，上限是多少"，再决定是否投入训练。

### 评测协议

三个划分必须**按会议 / 会话和说话人**互斥，不能按语句互斥，否则同场的声学条件和人名会泄漏。搜索集供提议者读取完整轨迹，建议从 AMI、AliMeeting、CHiME-6、DiPCo 的 dev 部分各取若干会话。选择集只返回聚合分数，作为严格改进门，并要求每个子数据集都不退化（参照 Voice Memory 的"没有任何领域变差"标准）。测试集包括 NOTSOFAR eval、AMI eval、LibriCSS 各重叠档位和 NYUAIRLAB-127 测试部分，每个候选族只报告一次，提议者不可读。另外保留一个**跨域闸门**：在英文上搜索得到的 harness，必须在阿拉伯语选择集上不退化，反之亦然，以此拦截 EvoPrompt 式的跨域崩溃。指标方面，英文报告 WER、cpWER/tcpWER、SWAP/100 词、重叠词错误率、删除率；阿拉伯语报告 WER + CER，以及语码转换片段上的转写容忍分数；所有改动都要报告有害编辑率和每小时音频的 GPU 时长。

### 风险与对策

奖励作弊是首要风险，在本项目中有四种具体形态。其一，**用删除换 SWAP**：两个干扰者时模型本来就倾向删除，提议者可能学会对重叠段输出空串，使 SWAP 下降而 WER 不降。因此必须把删除率和 SWAP 一起放进 Pareto 约束。其二，**词表泄漏**：如果候选词表从参考转写中抽取，B-WER 会虚假下降。词表只能来自议程、幻灯片、讲义等独立来源，并对 diff 做审计，拦截硬编码的语句 ID 或关键词列表（Meta-Harness 指出代码空间的过拟合比权重空间更容易审计）。其三，**篡改度量**：归一化器、对齐器、SWAP 统计脚本放在只读目录，用校验和锁定，提议者没有写权限（这正是 DGM 删除检测标记一事的教训）。其四，**阿拉伯语 MSA 化与正字法套利**：LLM 纠错或规则记忆可能通过统一拼写获得"收益"，所以需要同时看 CER 和人工抽检，并禁止归一化规则进入可搜索空间。过拟合方面，参照 HarnessCompass 的样本 / 留出差距，预期 selection 集的收益在 test 集上打对折，只接纳与数据集无关的修改。成本方面，按 Meta-Harness 的规模（约 60 个候选 / 20 轮）粗估，在 JUBAIL 上用作业数组并行评测是可行的。按项目约定，所有计算都通过 Slurm 提交，不在登录节点运行；提议者 agent 的主循环本身也应放在一个长时 CPU Slurm 作业中（可复用仓库现有的 CPU step driver），只负责编辑候选代码、提交 GPU 评测作业和读取轨迹。安全方面，HGM 仓库明确警告它会执行模型生成的不可信代码，因此候选代码应在受限容器中运行，并且无权访问测试集路径。

## 结论

这项调研改变的核心认识是：在本项目的场景中，"Harness + RSI 能否继续提升准确率"取决于外层脚手架能否获得模型本身拿不到的信息，而不取决于循环迭代多少次。纯文本纠错和 prompt 措辞搜索只是在重新排列模型已经输出的东西，SWAP 也因此无法用它们修复。真正的增量来自新信息源：会议议程和幻灯片中的词表、近场通道或阵列带来的 SIR 增益、目标说话人的参考音频，以及阿拉伯语上更强的外部教师。RSI 的角色是在锁死的验证器下自动发现如何组合和路由这些信息源。它的收益会在几十轮后饱和，但这些修改是可审计的代码，可以迁移，也能沉淀为工程资产。

还有两个结论超出了现有文献。第一，本项目实验中的 5 dB 阈值和"1.7B 比 0.6B 更爱 SWAP"的发现，使"以 SIR 为路由信号的自改进 ASR harness"成为一个有明确因果依据、且笔记范围内未见先例的研究点，适合作为论文贡献。第二，英文与阿拉伯语需要不同的主杠杆：英文远场的瓶颈在"跟谁"，阿拉伯语的瓶颈在基座和评测口径。所以同一套元脚手架应共享协议和验证器，搜索空间则必须分别设计。若强行用一个统一的 prompt 优化器同时覆盖两种语言，最可能的结果就是 EvoPrompt 式的跨域退化。
