语音流水线的 Harness 与 RSI

怎样在 Qwen3-ASR + Audar 的会议转写流水线外面，搭一个能自动变好的控制层；以及在动手之前，Harness 和 RSI 到底是什么。

适用场景：会议室、论坛、讲座；近场与远场麦克风；领域词表；阿拉伯语、英语为主，兼顾中文。文献检索截至 2026 年 11 月。

文献 已发表论文或厂商资料中的数字 本项目实验 我们自己测的 我们的提议 设计或推算，尚未测量

一页结论

  1. Harness 是包在模型外面的程序：决定模型看到什么、调用哪个工具、出错时怎么回退、结果怎么检查。RSI（递归自我改进）是让系统自己提出修改、用评测器打分、只保留变好的修改，再在新版本上继续改。
  2. 这套方法确实有效，但收益是有上限的台阶：几十轮迭代后就饱和，而且天花板由评测器决定。评测器能被钻空子时，系统会学会作弊。
  3. 没有论文在完整的"说话人分离 → 语种识别 → 多个识别模型分流"流程外面做过 Harness 或 RSI 闭环。各个环节都有零件，没有人把它们接起来。
  4. 我们流水线里最贵的错误是两类"流畅但错得离谱"的输出：Audar 把中英文翻译成阿拉伯语，以及远场重叠时转写成另一个人的话（SWAP）。纯文本检查发现不了它们，所以控制层必须看声学证据：语种后验和信噪比。
  5. 建议先手写两道有因果依据的闸门（语种闸门、信噪比闸门），再让 RSI 去搜索阈值、回退顺序和代码。
第一部分 · 入门

Harness 是什么

先用一个比喻。把识别模型想成一位厨师：手艺是训练出来的，短期内改不了。但同一位厨师在不同的厨房里，出菜质量可以差很多。

模型

厨师本人。能力由训练决定，改它要重新训练，代价高。

Harness

厨房和流程：备什么料、按什么顺序做、哪道菜交给哪位厨师、出菜前谁来试味。

RSI

厨房根据每天的试菜记录，自己修改流程和分工，只保留让菜变好的改动。

学术上的定义来自 2026 年 3 月的 Meta-Harness 论文：harness 是"包住语言模型、决定模型看到什么上下文的有状态程序" [Meta-Harness]。放到语音识别里，它包括下面这些部分：

HARNESS：模型之外、由我们写的程序
输入准备切分音频、选麦克风通道、语音分离
上下文把领域词表、议程、幻灯片里的术语放进提示
路由这一段交给 Qwen3-ASR 还是 Audar
工具说话人分离、语种识别、对齐器、LLM 纠错
识别模型权重冻结
验证文字体系对不对、有没有复读、长度是否合理
回退验证没过就换模型、换通道或重新解码
记忆积累下来的纠错规则和领域知识
轨迹每一段的所有中间决策都记下来，供复盘

只改 harness 能差多少？ 文献 Meta-Harness 引用的一个例子里，同一个模型只换 harness，成绩相差 6 倍。它自动搜出来的 harness 在文本分类上得 48.6，人工设计的 ACE 是 40.9，而且用的上下文少 4 倍。HarnessCompass 在 SWE-bench Verified 上把留出集成绩从 51.6% 提到 60.4% [HarnessCompass]。OpenAI 和 Anthropic 2026 年也都把 "harness engineering" 当作独立的工程方向来讲。

对语音识别来说，我们在实验里已经见过 harness 的威力：Audar 让它自己判断语种时，会把 82% 的中文对话句子输出成阿拉伯语；只要在调用前强制指定语种，这个错误就消失。模型一点没变，变的是外面的规则。

RSI 是什么

RSI 是 recursive self-improvement 的缩写，意思是递归自我改进。核心是一个循环：系统提出对自己的修改，评测器打分，变好了就保留，然后在新版本上继续提修改。"递归"指的是改进后的系统又成为下一轮改进的起点。

1 提议
提议者写出修改

通常是一个编码 agent 或 LLM，读取历史版本和它们的运行轨迹，提出新版本：改阈值、改代码、改提示，或生成训练数据。

2 执行
在搜索集上跑

新版本在一批带标注的数据上运行，留下完整轨迹。

3 评测
锁死的评测器打分

评测器由人写好、提议者无权修改。语音里就是固定的文本规整器和 WER 统计脚本。

4 晋升
过门才保留

在另一份没见过的选择集上也不退化，才算真的变好，进入存档。

↻ 存档里的版本成为下一轮的起点

被修改的对象可以分成四层，从便宜到昂贵：

层级改什么代表方法代价
L0 参数阈值、数值配置Optuna 等贝叶斯优化极低，可以在缓存结果上反复重放
L1 代码流程逻辑、路由、回退顺序Meta-Harness、Darwin Gödel Machine（DGM）、AlphaEvolve、ADAS中等，每个候选要重跑一部分
L2 上下文提示词、词表、规则记忆GEPA、ACE、Voice Memory低，几百条标注就够
L3 权重模型本身伪标签自训练、STaR / ReST、GRPO 强化学习高，需要 GPU 训练，有遗忘和崩溃风险

Harness 和 RSI 结合起来，就是"让 harness 自己进化"：模型权重先不动，让 agent 反复改外层程序，用评测器把关。这是 2025–2026 年最活跃的方向，因为它比训练模型便宜得多，也更容易审计。

范式的五个要素

不管具体用哪种方法，一个能用的 Harness + RSI 系统都离不开这五样东西。设计时逐条检查，比挑哪个算法更重要。

  1. 可修改对象：明确允许改什么（阈值、某几个文件、提示模板），其余一律只读。改动越小、越容易审计，越安全。
  2. 提议者：通常是编码 agent。Meta-Harness 的消融实验说明，让它读原始运行轨迹远比只给分数有用：中位数 50.0 对 34.6；给 LLM 写的摘要也只有 34.9。
  3. 评测器：决定系统往哪里进化，也决定天花板。必须锁死，提议者碰不到。DGM 就出过事：它通过删掉幻觉检测标记来"完成"任务 [Sakana DGM]。
  4. 三份互不重叠的数据：搜索集给提议者看，选择集用来决定是否保留，测试集最后只报一次。语音数据要按会议和说话人切，不能按句子随机抽，否则同一个人的声音会同时出现在两边。
  5. 晋升门与存档：只接受在选择集上严格变好、且各子集都不退化的修改；所有历史版本都留着，可以回滚，也可以从旧版本分叉。

从这些结果可以读出三条规律。第一，收益在几十轮内饱和，没有看到无限复利。第二，评测器越容易被钻空子，越会学到作弊；验证器的质量就是天花板。第三，搜索集上的提升会打折扣，要以留出集为准。

放到语音上的特殊之处

  • 好处：每个模块都有现成的局部指标。说话人分离有 DER，语种识别有准确率，识别有 WER。可以先找出哪个模块拖后腿，再把搜索预算花在那里。
  • 好处：解码结果可以缓存。两个模型在所有片段上各跑一遍存下来，之后调阈值只是在 CPU 上重放选择逻辑，几乎不花钱。
  • 难点：标注少，评测器难建。没有参考文本时只能用模型间一致性或 LLM 评审代替，但每个被接受的改动都要在一小批人工标注上再确认。
  • 难点：最严重的错误在文字上看不出来。翻译成阿拉伯语的句子、转写成另一个人的话，都是流畅合法的文本。只看文字的纠错器和评审无能为力，必须引入声学证据。
第二部分 · 我们的流水线

两类灾难性错误

现有流程是：说话人分离 → 语种识别 → 分流到 Qwen3-ASR（中文、英文等）或 Audar-ASR（阿拉伯语）→ 后处理。两个识别模型各有所长 本项目实验：

测试集指标Audar-ASR-V1-TurboQwen3-ASR-1.7B
Casablanca 阿联酋方言WER30.245.7
SADA 沙特电视WER28.943.2
Mixat 阿英混说WER17.122.2
FLEURS 阿拉伯语朗读WER6.59.7
ASCEND 中文对话（双方都指定语种）MER14.46.8
FLEURS 英语（双方都指定语种）WER6.74.8

分流本身没有问题，问题在于分错的代价极不对称：

82%

Audar 自动判断语种时，ASCEND 中文对话句子被输出成阿拉伯文（多为翻译）。FLEURS 普通话 63%，FLEURS 英语 23%。

28%

远场重叠句子里，Qwen3-ASR 至少有一处转写成了干扰者的话（SWAP）。约每 100 词 15.6 个错误。

5 dB

目标比干扰者响 5 dB 以上时，SWAP 基本消失（受控重混：0 dB +8.8，5 dB +2.1，10 dB +0.6）。

这两类错误有共同点：输出流畅、置信度高，任何只看文字的检查都放行。相比之下，幻觉、空输出、语种识别错误加起来不到 0.3%。所以这条流水线上，harness 的首要任务不是把平均准确率再抠高一点，而是拦住这两种灾难性失败。

已有论文做到哪

按环节梳理，结论很一致：单个环节的方法很成熟，跨环节的控制和自我改进几乎空白。

与我们最接近的是 MLC-SLM 2026 比赛的 HINTT 系统：DiariZen 微调 → 微调后的 Qwen3-ASR → LLM 纠错，tcpWER 15.28，好过统一的端到端模型（18.50）。说话人分离经微调后 DER 从 17.04 降到 3.25，LLM 纠错只贡献约 0.2。但它是人工调参的一次性工程，没有自动改进循环，也没做"把某个模块换成真值看损失多少"的消融 [HINTT]。另一个系统把 Qwen3-ASR-1.7B 接在分离前端后面做 GRPO，tcpMER 改善 6.83 个点，主要收益来自监督微调 [2607.08208]。

能直接写成论文章节的空白：

  1. "通用模型 + 专用模型"之间语种分流出错的损失有多大，以及由此推出的不对称阈值。
  2. "输出错误语种或翻译"的标准指标。我们提议叫输出文字不匹配率（SMR）。
  3. 以 cpWER/tcpWER 为目标、带锁死评测器的自我改进循环。
  4. 识别修正说话人标签 → 再训练分离模型的多轮闭环。
  5. 把信噪比当作路由变量来抑制 SWAP，并验证它的因果效果。
  6. 公开的阿拉伯语多人会议说话人分离评测集。

Audar 的定位：只执行，不裁决

文献 Audar-ASR-V1-Turbo 由 0.32B 编码器和 2.03B 解码器组成，与 Qwen3-ASR-1.7B 的结构一致，附带 Qwen3-ASR 的代码，用 qwen-asr 或 vLLM 推理。训练的最后一步是偏好对齐（KTO），奖励阿拉伯语的书写规范 [Audar 模型卡]。厂商自己写明：强制指定语种是必须的；输出 language None 时要当作空结果，否则音乐或静音会引发复读。模型卡没有公布任何中英文结果，也没说明热词功能的效果。许可证限制大规模商用。

我们的推断 Audar 很可能是 Qwen3-ASR-1.7B 的微调版。由此得出几条设计约束：

  • 语种只由 Qwen3-ASR 判断，Audar 只在判为阿拉伯语时、以强制阿拉伯语的方式调用。
  • 两个模型的置信度不能直接比大小，偏好对齐改变了 Audar 的置信度分布。
  • 两者同源，错误很可能相关。拿"两个模型结果一致"筛伪标签不够可靠，要再加一个不同结构的模型（例如 CTC 模型）做验证。
  • Qwen3 的强制对齐模型只支持 11 种语言，不含阿拉伯语。阿拉伯语逐词时间戳要换 MMS 或 wav2vec2 阿拉伯语对齐器。

Harness 架构：七个模块、两道闸门

我们的提议 骨架是确定性的流程，上面挂着可以被自动搜索的策略点；每个片段都留下完整轨迹。

M4上下文构建从议程、幻灯片、讲义、名单建词表，按片段检索 top-k
→

→

橙色框是两道闸门，它们看的是声学证据，不是文字。窄屏时可以左右滑动查看。

闸门一：语种闸门的规则

阈值不取 0.5，而由不对称代价推出。阿拉伯语片段送 Audar 的收益 G 约 10 个 WER 点（本项目实验中是 3–15 点）；中英文片段被误送 Audar 的损失 L 约 100 点（几乎整句变成翻译）。

送 Audar 的条件：P(ar) > L / (G + L) ≈ 100 / 110 ≈ 0.9
  1. P(ar) 在中间带（例如 0.4–0.9），或片段短于约 2 秒：两个模型都跑，按文字体系和交叉打分选一个。
  2. 短片段优先沿用同一说话人或相邻片段的语种，不逐段重新判断。
  3. 阿语为主的阿英混说送 Audar（Mixat 上 17.1 对 22.2），英语为主的送 Qwen3。
  4. Audar 输出后再查"翻译签名"：判为中英文却输出了阿拉伯文，或长度与 Qwen3 的结果严重不符，就丢弃并退回 Qwen3。

闸门二：信噪比闸门的规则

  1. 对标出的重叠段估计信噪比：有近场通道就用近远场能量比，没有就用分离后各路的能量比。
  2. ≥ 5 dB：直接识别。
  3. < 5 dB：依次尝试切换到近场通道、分离或提取目标说话人后重新识别。分离前端会带来失配，需要用分离后的音频适配识别模型（USTC 这样做后 tcpWER 从 16.57 降到 12.07）。
  4. 三人以上同时说话的片段标为低可信度，不强行转写。
  5. SWAP 探针：对齐假设中的每个词，比较这个词的声音更像目标说话人还是干扰者；1.7B 与 0.6B 在重叠段上分歧大时也可疑。探针要先在我们的重混数据上校准，那里每个词属于谁是已知的。

词表注入与验证器

Qwen3-ASR 训练时用过带上下文的数据，但论文没有报告效果数字。外部对比发现语音大模型对词表里的干扰词数量和词的顺序都很敏感 [Huber & Waibel]，所以 top-k 数量、排序和模板都应该交给搜索。大词表要先检索再注入。Audar 的上下文功能效果未知，需要单独测。

LLM 纠错只在拿得准的地方用：不带置信度的纠错曾把 WER 从 10.83% 推到 20.01%，加入逐词置信度后回到 10.58%。CHiME 综述也指出，LLM 后处理在真实远场会议上只有边际收益。

打分：一组指标，而不是一个 WER

  • 主指标按语种分开：英文用 tcpWER/cpWER（MeetEval），中文用对应的 CER，阿拉伯语用统一规整后的 WER 加 CER。
  • 说话人：DER、说话人数误差，以及 cpWER 与不计说话人 WER 之差（单独衡量归属错误）。
  • 语种：按 <1 秒、1–2 秒、2–5 秒、>5 秒分桶的语种错误率；SMR（输出文字与真实语种不符的句子比例）。
  • 重叠：每 100 词 SWAP 数、重叠词错误率、删除率。
  • 词表：术语错误率与非术语错误率，防止为了术语牺牲其余部分。
  • 成本：RTF、每小时音频的 GPU 秒数。

功劳怎么分给各模块：真值替换阶梯

在带标注的开发集上，依次把语种识别、说话人分离、路由（两个模型里取较好的）、输入（近场或理想分离）换成真值。相邻两级的差值，就是这个模块还能挖的空间。搜索预算按这个空间分配。HINTT 正好缺这一步。只有当某个局部指标的变化与整体指标高度相关时，才拿它代替整体指标去优化；文献已经发现 DER 最优和 WER 最优的分段设置可能方向相反。

防过拟合、防作弊

  • 搜索集、选择集、测试集按会议和说话人互斥。搜索集可以混入重混合成数据，选择集和测试集只用真实录音。
  • 阿拉伯语固定留出整套数据集（例如 Casablanca-UAE 和 Mixat）作为域外测试，不按句子抽样。
  • 跨语种闸门：在英文重叠数据上找到的改动，必须在阿拉伯语和中文选择集上不退化，反之亦然。
  • 文本规整器、MeetEval、对齐器、SWAP 统计和 SMR 脚本放只读目录，用校验和锁定。评测器自己要升级时，每次都要在人工标注的锚点集上验证。
  • 权重层：伪标签必须来自多个不同视角；每轮都回放原始数据（LoRA 加回放让遗忘减少 55%）；伪标签占比设上限。

成本

我们的估计 先缓存、后搜索。约 26 小时阿拉伯语数据用两个模型各跑一遍，按实测速度约 26 × (0.25 + 0.19) ≈ 11.4 GPU 小时（A6000，transformers；换 vLLM 会少很多）。缓存之后，L0 的几百次阈值试验只在 CPU 上重放。L1 按 Meta-Harness 的规模（约 60 个候选、20 轮）估计是数百 GPU 小时，在 JUBAIL 上用作业数组并行。提议者 agent 的主循环本身也放在 CPU Slurm 作业里，不在登录节点运行。

结论

在"通用模型 + 专用模型"的语音流水线里，harness 的首要职责不是提升平均准确率，而是管住代价极不对称的灾难性失败。Audar 的翻译式输出和远场 SWAP 都是流畅、高置信度的文本，只有能看到声学证据的控制器才拦得住。这也是现有单路识别的自改进工作（Voice Memory、纠错提示进化）在这里不够用的原因：它们优化的是"已经说对了是谁、说对了哪种语言"之后的文字。

由此可以形成一个能投稿的研究框架：带声学闸门的自改进路由 harness。它包含三个可以分别验证的命题：

  1. 语种分流出错在通用/专用模型之间的传播代价，以及由此推出的不对称阈值；
  2. 信噪比作为路由变量对 SWAP 的因果效果，以及 SWAP 探针的准确度；
  3. 在锁死的评测器下，阈值、代码、上下文三层搜索的搜索集与留出集差距。

三个命题都能用现有的 11 个阿拉伯语测试集、FLEURS 和 ASCEND，以及三项重叠实验直接起步。只有阿拉伯语多人会议这一块，需要自己采集并标注一小批数据。
